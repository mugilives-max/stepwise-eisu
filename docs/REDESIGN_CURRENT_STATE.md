確認日: 2026-09-07。コードの基準は `stepwise-eisu` の `30e1ce8`。作業全体では同日に読み取り専用の `git ls-remote` でリモートmainとの一致を確認しました。以下の行番号はこのコミットのものです。保護者認証の変更は別作業で進行中で、下表は変更前を示します。前の会話ではApps Scriptの公開バージョン44を確認していますが、本番GASのコードと基準コミットの一致は未照合です。実データの状態と現在のデプロイの再確認はこの調査では行っていません。

## 結論

予約、生徒カルテ、宿題、請求の土台はあるため、既存の `slots.id` を使って授業記録を追加できます。ただし、画面上の「授業の記録」は現在、実施日時と科目の一覧です。授業内容・理解状況・次回準備を保存する機能はこれから作る必要があります。

授業は新規案内 `offered` → 生徒承認 `booked` → 先生が `done` を付ける流れです。生徒の辞退は行削除、先生の解除は `open` へ戻して所有者を外します。新規案内はメール、生徒の承認はCalendar作成と先生向け通知、保護者の回数回答も先生向け通知を伴います。根拠は `adminOffer_:1288–1336`、`accept_:280–299`、`decline_:302–311`、`parentPlanDecide_:671–687` です。

`stepwise-mcp` はローカルのコミット `c3fc9e0` を読み取り確認し、未コミット変更はありませんでした。`src/tools.ts:33–124` に閲覧7ツール、`src/gas.ts:46–56` に秘密項目の除外があります。リモート・Cloudflareの稼働版との一致は未確認です。

## Drive提案との対応

2026-09-07にGoogle Drive連携で[将来システム提案書](https://drive.google.com/file/d/1wBUx3jFjb8lL8CasHYEJ7DzCS43A476M/view)と[初回作業指示書](https://drive.google.com/file/d/13VvQM3BQW2opM-y7PSv75KzVaNKOJdNT/view)の本文を取得して照合しました。いずれも同日作成のMarkdownです。初回指示書が指摘する古いテスト用 `server.js` や `index.html` を本番の根拠には使っていません。

| 提案の流れ | 使える既存機能 | 追加するもの |
|---|---|---|
| 授業前の確認 | 予約日時・科目、生徒カルテ、未完了宿題 | 前回の授業記録と引き継ぎ欄 |
| 授業内容の記録 | `slots.id`、生徒ID | 教師用の記録保存・再編集・履歴 |
| 宿題へ反映 | 既存 `tasks` と生徒ホーム | 授業記録内の項目IDとtasksの対応 |
| 保護者報告の下書き | 先生画面 | 内部メモを含めない定型下書き |
| 次回へ引き継ぐ | 次回の確定予約 | 前回記録＋現在の未完了宿題の合成表示 |

完成形提案の「保存と同時に宿題を自動登録」は、初回では「記録内の宿題下書きを保存 → 確認して生徒へ反映」に分けます。書きかけの課題が生徒に届くことと、途中失敗時の判別不能を避けるためです。また、必須項目は授業内容に絞り、報告の公開・保護者独立ポータル・複数講師・AIは後続候補とします。これは初回指示書の「提案を既定事項として実装しない」「下書きと公開を区別する」に沿った変更案です。

初回の具体仕様は [LESSON_CYCLE_PHASE1_SPEC.md](LESSON_CYCLE_PHASE1_SPEC.md)、全体の順序は [REDESIGN_MASTER_PLAN.md](REDESIGN_MASTER_PLAN.md) を参照してください。
