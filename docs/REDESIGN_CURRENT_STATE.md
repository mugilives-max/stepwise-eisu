## 結論

基準コードには予約、生徒カルテ、宿題、請求の土台があり、既存の `slots.id` を授業記録の接続キーに使えると判断しました。当時の「授業の記録」は実施日時と科目の一覧で、授業内容・理解状況・次回準備の保存機能はありませんでした。

基準コードの授業は新規案内 `offered` → 生徒承認 `booked` → 先生が `done` を付ける流れでした。生徒の辞退は行削除、先生の解除は `open` へ戻して所有者を外します。新規案内はメール、生徒の承認はCalendar作成と先生向け通知、保護者の回数回答も先生向け通知を伴います。根拠は `adminOffer_:1288–1336`、`accept_:280–299`、`decline_:302–311`、`parentPlanDecide_:671–687` です。

`stepwise-mcp` はローカルのコミット `c3fc9e0` を読み取り確認し、未コミット変更はありませんでした。`src/tools.ts:33–124` に閲覧7ツール、`src/gas.ts:46–56` に秘密項目の除外があります。リモート・Cloudflareの稼働版との一致は未確認です。
