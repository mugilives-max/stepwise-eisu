# 切り替えの手順書と案内文（作り直し v2）

今の仕組み（`/kanri/`・`/hogosha/`・`/yoyaku/`）から、新しい仕組み（`/staff/`・`/family/`・`/student/`）へ、**月初に一度で切り替える**ための手順です。設計は [REBUILD_DESIGN.md](REBUILD_DESIGN.md) の 6 章。8段目で写す道具・照らし合わせ・予行を、9段目で切り替えのボタン・元に戻すボタン・今の画面からの案内をそろえました。

## 1. いつ切り替えるか

- **月初の3日〜5日**。今の仕組みで前月分の請求が確定した（3日の0時10分）あと。
  - こうすると、前月分の請求は今の仕組みで確定したものをそのまま写せる。新しい仕組みは、その月の分から計算する。
- 授業の少ない日の、授業のない時間（朝など）。作業は1時間ほどを見込む。

## 2. 前の週までにすること

1. **リハーサルを2回**（本番のデータで。何度でもやり直せる。今の仕組みは変わらない）
   1. 「移行」で「全部を順に写し直す」。
   2. 「5. 照らし合わせ」で、すべて「同じ」か「決めた差」になっているか確かめる。
   3. 「6. 切り替えの予行」で、ログインできる保護者・カレンダー・残っている対応を確かめる。
   4. 新しい画面を見て回る（予定・記録・成績・計画・請求・報酬）。おかしいところは直してもらう。
2. **講師**を「スタッフ」で招待し、「報酬」で時給を決める。
3. **保護者のメールアドレス**がない家族は、「家族と生徒」で入れる（新しい仕組みのお知らせはメールで届くため）。
4. 保護者・生徒・講師に**予告**を送る（下の案内文 A）。

## 3. 当日の手順

当日の作業の大部分は、新しい管理画面の「移行」→「7. 切り替え」のボタン1つで行います（9段目で作った）。

1. 「移行」で「6. 切り替えの予行」を押し、残っている対応（連絡・キャンセル料の判断）があれば先に済ませる。
2. 「7. 切り替え」で、登録していない家族に案内を送るかを選び、「切り替える」と入れてボタンを押す。ボタンは次を順に行う。
   1. 今の仕組みを「読むだけ」にする。今の画面からの書き込みと、今の仕組みの毎日の自動処理（請求の確定・仮予定の決定）が止まる。管理画面のログインと閲覧は残る。
   2. 最後の「全部を順に写し直す」。
   3. 照らし合わせ。「違う」が出たら、そこで止めて今の仕組みを元に戻す（何も切り替わらない）。
   4. 切り替える（保護者へのメール・カレンダーが動き始める）。
   5. 今日以降の決定の授業・面談で、カレンダーの予定がないものの予定を作る（今の仕組みが作った予定はそのまま引き継ぐ）。
   6. （選んだとき）保護者ページに登録していない家族に、登録の案内を送る。
3. 今の画面は自動で新しい画面へ案内する（`/hogosha/` → `/family/`、`/yoyaku/?k=` → `/student/?k=`、`/yoyaku/#family` → `/family/`）。`/kanri/` は移さず、上に「読むだけです・新しい管理画面へ」と出す。
4. 自分で一通り試す（新しい画面でログイン・予定を見る・記録を書く、テスト用の家族で保護者ページ）。
5. 保護者・生徒・講師に案内を送る（案内文 B・C・D）。

## 4. うまくいかなかったとき（戻し方）

- **当日のうち**なら、今の仕組みに戻せる。「7. 切り替え」の「元に戻す」（「元に戻す」と入れる）で、次の2つを一度に行う。
  1. 新しい仕組みの保護者へのメール・カレンダーを止める。
  2. 今の仕組みの「読むだけ」を外す（書き込みと毎日の自動処理が戻る）。
- 新しい仕組みで受けた連絡や記録があれば、今の仕組みに手で入れ直す。新しい仕組みが作ったカレンダーの予定は残るので、要らなければ消す。
- 戻しても、新しい仕組みの台帳は残る。直してから、もう一度「全部を順に写し直す」からやり直せる。

## 5. 切り替えたあと

- 今の画面は1か月ほど**読むだけ**で残す。そのあとで止める。
- **写さないもの**（決めたこと）: 成績推移・模試・面談記録・成績票の読み込み（成績は作り直す）、授業希望・連絡欄（やめた機能）、先生が登録した授業の控え（処理の控え）、保護者あての送信の控え（今の台帳に残して、必要なら見る）、ログ。
- 今の台帳（D1 `stepwise`）は消さずに残す。D1 は30日まで前の状態に戻せる（タイムトラベル）。
