## 1. このシステムの目的

個別指導の運営（予定・授業記録・計画と料金・請求）を、先生がほぼ1人で、少ない手間で回せるようにする。

- やり取りの中心は LINE のままでよい。システムは「決まったことの台帳」と「保護者・生徒が見る窓口」。
- 契約は1か月ごと。料金は毎月の授業計画で決め、保護者が承認する（規約案の第1条）。
- 講師が増えても回る形にする（担当・代講・引き継ぎ）。

## 2. 使う人と役割

| 役割 | 何をする | ログイン |
|---|---|---|
| 先生（代表） | すべて。設定・請求・講師の管理を含む | メール＋パスワード（強くする。7章） |
| 講師 | 担当授業の記録・引き継ぎメモ・担当生徒の宿題と成績の閲覧 | メール＋パスワード |
| 保護者 | 契約者。授業計画の承認、請求の確認と支払いの連絡、予定の確認と連絡、子どもの記録・成績の閲覧、生徒の操作の制限 | メール＋パスワード |
| 生徒 | 予定の確認と連絡、宿題、授業記録・成績の閲覧 | 専用リンク（今のまま。8章で相談） |

**家族が根っこ**。

- 家族（契約者）の下に生徒がいる。
- 計画の承認・請求・連絡先・規約の同意は、家族の単位で持つ。
- 生徒を登録するときは、まず家族を決める。

## 3. 業務の流れ（毎月）

1. **1〜2日**：先生が前月分の請求を確かめる。3日の0時10分に自動で確定し、保護者ページに出る。
2. **〜20日ごろ**：先生が翌月の授業計画（科目・回数・料金）と予定表を作り、送る。
3. **〜25日**：
   - 保護者は授業計画を承認する。
   - 予定は、連絡がなければ締め切りの翌日に決定する。
   - 都合の悪い日だけ「変更・お休みの連絡」を使う。
4. **授業の日**：先生または講師が授業をして、記録を書く。宿題を出し、次の担当への引き継ぎメモを残す。
5. **当日の変更**：
   - 前日23時までの日時の変更・お休みは無料。
   - それ以降はキャンセル料がかかる。
   - 開始を遅らせる場合は、料金は予定どおり。
6. **支払い**：保護者が振込を連絡し、先生が入金を確認する。

## 4. 必須の機能（毎日・毎月使う）

### 予定

- 全体と生徒ごとの予定表（月）。
- 仮予定を送る。今すぐ送るか、予定表にまとめて送るかを選べる。
- 締め切りで自動決定、直接決定、日時の変更、削除。
- 「変更・お休みの連絡」の受け付けと処理（日時の変更のお願い・お休み・開始を遅らせたい・キャンセル）。
- 先生の休みの登録。**今は登録の画面がない**。
- 生徒・保護者による「予定の共有」（テスト・行事・授業ができない日）。授業希望の入力はやめる。
- カレンダーと Meet（オンライン授業）。

### 授業記録

- 扱った範囲・コメント・宿題を、保存して公開する。下書きもできる。
- 先生用メモ（理解度・様子・次回の焦点など）。
- 前回の記録・未完了の宿題・月の予定を参照する。
- 宿題の出題・確認・やり直し。生徒の「できた」の入口は1つにする。

### 計画・料金

- 毎月の授業計画を作り、送る。追加の計画も作れる。
- 保護者の承認・回数の調整・見送り。LINE・電話での承諾は先生が記録する。
- **料金は計画で決める**。
  - 授業の種類ごとの標準時間・標準料金は、計画を作るときの初期値。
  - 生徒ごとの「基本単価」はなくす方向（相談。8章）。
- 先月と同じ内容で翌月の計画の下書きを作る。

### 請求

- 月ごとの請求。家族でまとめ、子ども別の内訳を付ける。
- 3日の自動確定。
- 入金・振込の連絡・入金確認。
- キャンセル料と、減額・免除の審査。

### 家族・生徒の管理

- 家族の登録。保護者の登録案内メールを送る。
- 生徒の登録（家族の下に）。基本情報（学年・学校・連絡先など）。
- 在籍・休会・退会。今は生徒を戻すボタンがない。

### 通知

- **先生あてのメール**：連絡を受けたとき。種類ごとにオン・オフできる。
- **保護者あてのメール**：計画の承認依頼、予定表、予定日の決定、請求。
- 生徒あてのメールとアプリ通知は、なくす候補（下の6章）。

### 設定・運用

- 授業の種類。
- 先生あてメールの設定。
- 送れなかった処理の再送と、送信の記録。
- 毎日の写し・週1のバックアップ。

## 6. やめる候補（作り直しでは作らない）

| 機能 | 理由 |
|---|---|
| 連絡欄（アプリ内のやり取り） | LINE があるため。オンラインを大きく広げるときに改めて考える |
| 生徒あてのメール通知 | 登録がなく、保護者あてで足りる |
| アプリ通知（プッシュ） | 登録がない |
| 保護者への報告文の下書き | 使っていない。授業記録の公開で足りる |
| 保護者の既読確認 | 使っていない |
| 学校予定表 PDF の読み取り（AI） | 精度が低くやめた |
| 模試の専用の記録 | 成績推移にまとめる（相談） |
| 授業希望（できる時間帯）の入力 | 日程の作り直しで決定済み |
| 旧・生徒ごとの保護者パスワード、旧キャンセル申請、旧ホーム、週間ボードなど | 画面から開けない残り |

## 7. 使いやすさ・安全・運用の要件

### ログイン（先生の要望で強化する）

- 先生・講師・保護者のパスワードは同じ強い方式で守る。今は先生だけが弱い方式。
- 端末ごとにログインを保つ。今の先生は端末1台だけ。
- 初期 PIN への後戻りをなくす。
- 失敗が続いたときのロック。
- ログイン画面を1つの分かりやすい流れにする。
  - 先生と講師は同じ入口。
  - 保護者は保護者ページの入口。
- 再設定はメールで行う。

### その他

- **スマホで使える**。保護者・生徒はスマホが前提。先生も外出先で予定と記録を触れる。
- **1人で運用できる**。
  - 毎月の手作業は「計画と予定表を作って送る」「請求を確かめる」だけに近づける。
  - 失敗した処理は画面で分かり、1件ずつ直せる。
- **速さ**。画面を開いて1〜2秒で使える。
- **個人情報**。生徒・保護者の情報は必要な人にだけ見せる。
  - 講師は担当生徒だけ。
  - 料金は保護者と先生だけ。
- **費用**。今の Cloudflare（月額）と Google の範囲で動かす。
- **記録が残る**。承認・請求・キャンセルなどお金に関わるものは、誰がいつ何をしたかを残す。

## 8. まだ決めていないこと（相談）

1. **両親それぞれのログイン**。1つの家族に保護者のログインを2人分持たせるか。今は1家族1つ。
2. **生徒のログイン**。今の専用リンクのままでよいか、生徒にもパスワードを持たせるか。
3. **生徒ごとの基本単価をなくすか**。計画と授業の種類の料金だけにする。
4. **講師の勤務実績と給与**。勤務時間の集計だけでよいか、給与の計算までするか。
5. **模試を成績推移にまとめるか**。
6. **作り直しの進め方**。
   - 土台（Apps Script をまねた仕組み）から作り直すか。
   - 家族を根っこにしたデータの形を先にするか。
   - 画面を先にするか。
