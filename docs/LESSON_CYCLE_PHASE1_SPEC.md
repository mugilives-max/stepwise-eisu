## ローカル追加: 授業準備（本番未反映）

2026-09-08のローカル実装。公開済みのv49とは区別する。

- `lessonContext` にJSTの `today` と先生専用の `preparation` を追加。翌日以降は準備の編集画面、当日以降は公開する記録の編集欄も表示する。既存の記録APIの日付制約は変更しない。
- 準備は最大4,000文字、空文字で内容を消せる。`lessonPreparationSave` は教師認証、在籍、現在の確定授業の所有者、日時・分数・科目の一致、`expectedRevision` を検証する。`expectedSlot` は `date/start/min/subject`。既存の `lessonWrites` を使い、同一requestIdの再送と中断後の再開で重複保存を防ぐ。
- 新規シート `lessonPreparations` の列順: `id, slotId, studentId, body, revision, updatedAt, lessonDate, lessonStart, lessonMin, subject`。idは `JSON.stringify([studentId,slotId])`。授業枠を別生徒へ割り当て直しても以前の準備を上書き・転用しない。日時・科目が変わった場合は保存時の情報との差異を表示し、内容の再確認を促す。
- 準備とその保存ジャーナルは先生専用。公開スナップショット、先生の実施記録、宿題、実施状態、承認・請求、Calendar、通知を変更しない。記録への自動コピー・公開もしない。生徒・保護者・MCPの閲覧用応答には準備本文を追加しない。
- 準備の入力はタブのメモリだけに保持し、端末の永続キャッシュへ保存しない。未保存時はページ離脱を警告する。通信失敗時は入力と同じ要求を保持して再試行、版競合時は最新の準備と比較し、明示的に採用または手元の内容で編集を継続する。
- 初回反映では台帳退避・見出しの事前照合・旧セル保持の確認が必要。新規シートを準備してからGAS・画面をまとめて切り替える。本番の追加シートはまだ作成していない。

## ローカル追加: 対面2人の記録（本番未反映）

- 管理画面の `#lesson-pair?slot=授業ID` から開く。教師専用 `lessonPairContext` は `slotId/otherSlotId` を受け、対面・確定・別生徒・実際に時間が重なることを検証する。終了と開始が同時刻の授業は同時受講に含めない。
- 相手が1人なら自動表示し、長い授業に別の生徒が順番に重なる場合など、候補が複数なら先生が選ぶ。最大2人を表示し、各生徒の日時・科目・前回記録・準備・未完了宿題・記録欄を分ける。相手なし・予定変更時は空の記録を作らず、選び直す。
- 個別画面と同じ入力・保存処理を使用する。各生徒の版・requestId・保存中／未保存／公開状態を分離し、他方の保存完了・失敗・再試行で入力欄を再生成しない。準備・先生メモは非公開、記録はその生徒だけへ保存時公開。一括保存・一括公開は行わない。
- ページ内の移動では入力をタブのメモリに保持し、ページ離脱時は既存の未保存警告を使う。授業の読込中に古い応答が来ても、保存中の要求や新しい保存結果で使った版を巻き戻さない。保存そのものの所有者・授業変更・版の検証は既存APIが引き続き行う。
- デスクトップは2列、狭い画面は縦配置。本文や準備を端末の永続ストレージへ追加せず、MCP・生徒・保護者APIへ教師用の2人分の応答を公開しない。

## 1. できるようにすること

先生がカルテまたは今日の授業から対象の確定授業を選び、前回の内容と未完了宿題を確認して、その授業の記録を残します。保存した授業内容・取り組みの様子・宿題欄・次回の焦点は、対象の生徒と保護者へ公開します。先生だけのメモと別の報告下書きは非公開です。宿題欄から既存の「やること」へ明示的に反映し、次回の準備で再利用します。

対象は全体計画の段階1と、2026-09-08に確定した保存時公開・次回授業期限です。先生のみが授業記録を編集します。従来の「記録は先生のみ、報告は下書きまで」という仕様は、今後新たに受理する記録保存に限って変更します。過去の未公開記録や報告下書きをまとめて公開しません。

### 設計判断の理由

- 予約と台帳を全面移行すると、Calendar・通知・請求への影響を同時に確認する必要が生じるため、既存の授業IDに記録を追加し、宿題は `tasks` を再利用します。
- 記録の宿題欄は本文の一部として保存時に公開します。「やること」の課題登録・更新・取り下げは引き続き別の明示操作とし、既存の完了状態を守ります。
- 入力負担を抑えるため必須は授業内容に絞り、取り組みの様子・次回の焦点などは任意にします。細かな採点項目やAIの自動判定を必須にしません。
- 公開版は公開項目だけを持つ別シートの不変スナップショットで保持します。先生メモを公開処理の生成元へ渡しません。報告下書きの保存は公開に結び付けず、授業記録の保存でもメール・LINEは送りません。

## 2. 画面と操作

1. **授業を選ぶ**: 既存 `slots.id` と生徒IDを渡す。生徒名・日時・科目・実施状態はサーバーの値を表示する。
2. **前回を確認**: 同じ生徒・同じ科目で、対象授業より前の最新の有効記録を表示。なければ「同じ科目の記録はまだありません」。他科目の記録は明示リンクから選ぶ。前回の次回メモと、現在の未完了宿題を併記する。
3. **記録を入力**: 授業内容は必須。取り組みの様子・理解できたこと、次回の焦点、先生だけのメモは任意。科目・日時をここで変更しない。
4. **記録を保存して公開**: 教師用記録と先生メモを保存し、先生メモを除いた公開版を対象生徒・保護者へ公開。保存成功後に版数・公開時刻を表示する。通信失敗時は入力を残し、同一リクエストで再試行する。
5. **宿題を生徒へ反映**: 保存済み宿題の差分と公開先を表示し、先生が押したときに `tasks` へ反映する。完了済みの再出題や取り下げは別の明示操作とする。
6. **報告下書き**: 授業内容・取り組みの様子・宿題・次回の焦点だけから定型文を生成。編集した下書きは自動生成で上書きしない。先生だけのメモは生成元に渡さない。「未公開」を表示する。
7. **次回準備**: 保存後の次回メモと現在の未完了宿題を確認。次回授業が未予約でもメモは保存できる。

「実施済みにする」「請求登録」は既存の別操作です。記録保存では `slots.done`、承認、請求額、入金、Calendar、メール、LINEを変更しません。

入力上限: 授業内容2,000文字、取り組みの様子1,000文字、次回の焦点1,000文字、先生メモ2,000文字、報告下書き4,000文字。宿題は最大10件、1件の題名80文字。期限は日付指定・次回の同じ科目の確定授業・指定なしを選び、日付指定は1900〜2199年の実在する日付です。上限超過や改行・タブ以外の制御文字は入力エラーとし、切り捨てません。

入力時間の目標は1〜2分ですが未計測です。管理画面では、過去の実施済み授業で記録がなければ「未入力」、有効記録ありなら「記録済み」、公開版があれば版数・公開時刻を表示します。報告下書きには引き続き「未公開」と表示します。過去の記録は今回の移行だけでは公開済みになりません。

## 3. 保存先とデータの責務

予約システムのスプレッドシートに次を追加します。既存の台帳や `slots` の列を並べ替えません。

| シート・列 | 用途 |
|---|---|
| `lessonRecords`: id, studentId, slotId, lessonDate, lessonStart, lessonMin, subject, content, progress, nextFocus, homeworkJson, revision, status, createdBy, updatedBy, createdAt, updatedAt, voidReason, lastRequestId, lastRequestHash | 1生徒・1授業枠につき1つの有効記録。日時等は初回保存時にサーバー側でコピー。statusはactive/void |
| `lessonPrivateNotes`: recordId, teacherNote | 教師専用メモ。記録と同じrevisionの保存処理に含めるが、公開用のデータ変換関数から参照しない |
| `lessonReportDrafts`: recordId, body, sourceRevision, revision, updatedAt | 教師だけが見る下書き。元記録が変わったら「記録更新あり」。編集済み本文の自動再生成はしない |
| `lessonWrites`: requestId, operation, payloadHash, payloadJson, status, resultJson, createdAt, updatedAt | pending/applied/failedを持つ書き込み記録。途中失敗の再開に必要な正規化済み内容を保持。アクセスは先生限定 |
| `lessonPublicSnapshots`: id, recordId, studentId, slotId, revision, lessonDate, lessonStart, lessonMin, subject, content, progress, nextFocus, homeworkJson, publishedAt, sourceRequestId | 今後保存した記録の公開版。idはrecordIdとrevisionから決定し、同じ版を上書きしない。先生メモ・報告下書き・作成者・トークンを含めない |
| 既存 `tasks` の9〜12列: sourceRecordId, sourceItemId, sourceRevision, withdrawnAt | 授業由来の宿題との対応。最初の8列・既存ID・doneAtを保持 |
| 既存 `tasks` の13〜16列に追加: dueMode, dueSubject, dueAfter, dueTime | 期限の定義、同科目、JST起点、完了時に固定した期限時刻。既存行は空欄のまま日付指定との互換を保つ |

`homeworkJson` は `{ itemId, title, due, type, dueMode? }[]`。dueModeは `date` / `nextLesson` / `none`。省略した従来入力はdueありならdate、空ならnoneと解釈し、旧requestIdの正規化済みハッシュを変えません。nextLessonの科目と起点は授業記録のサーバー側の値を使い、項目入力で上書きできません。初回に画面で安定した項目IDを発行し、並べ替え・題名変更でも同じIDを使います。新規課題は新しいIDです。IDは単なる行番号にしません。

無効化した記録は通常保存で復活させません。再作成は現在の授業枠の所有者・状態を再検証し、新しいrecordIdとexpectedRevision=0で開始します。過去の無効記録と紐付いた宿題は保持し、新しい記録に自動移管しません。

ID・本文・日時のスナップショットは文字列、minとrevisionは整数、createdAt/updatedAtはサーバー時刻です。createdBy/updatedByは現在の単一先生アカウントを指す固定識別子 `teacher:primary` をサーバー側で設定し、将来の複数講師導入時にIDを置き換えます。トークンやメールを作成者欄へ保存しません。無効化操作の理由と実行者も書き込み記録に残します。

既存列との対応は `students.id → lessonRecords.studentId`、`slots.id → slotId`、`slots.date/start/min/subject → lessonDate/lessonStart/lessonMin/subject` です。既存 `tasks` の8列は移し替えず、末尾の関連列だけを追加します。成績・模試・入金・面談の列は初回変更しません。

lessonRecordsを教師の授業内容の正本、lessonPublicSnapshotsを公開済み本文の正本、tasksを「やること」の課題内容・完了状態の正本とします。tasksを記録から毎回作り直したり、doneAtを記録側に複製して同期したりしません。内部メモ・下書き・書き込み記録は既存の生徒state、parentData、MCP、カルテの端末キャッシュへ一括で混ぜません。公開記録は対象生徒を認証で確定してから専用の投影関数で返します。

## 4. APIの契約

すべて先生の `action: admin` と有効なtokenを要求します。MCPの許可一覧には追加しません。

| op（新規） | 主な入力 | 返すもの |
|---|---|---|
| `lessonContext` | studentId, slotId、任意recordId | 対象授業、当該記録、前回記録、未完了宿題、現在revision、宿題反映状態、下書き、全件の授業選択肢。slotIdが空なら直近の対象を選び、対象なしはslot:null |
| `lessonRecordSave` | studentId, slotId, expectedRevision, requestId, record | 保存済みrevision、publishedRevision、publishedAt、反映待ち宿題差分。初回expectedRevisionは0。新たに受理した保存は旧画面からの入力も公開対象 |
| `lessonHomeworkApply` | studentId, recordId, expectedRevision, requestId | 追加・更新・保留・失敗の項目ID、最新tasks、再試行の要否 |
| `lessonHomeworkWithdraw` | studentId, recordId, itemId, requestId、任意expectedRevision | 明示的に取り下げた結果。doneAtは保存。新画面はexpectedRevisionも送る |
| `lessonReportDraftSave` | studentId, recordId, expectedDraftRevision, sourceRevision, requestId, body | draftRevision、保存時刻。sourceRevisionは現在の記録版と一致が必要。公開しない |
| `lessonRecordVoid` | studentId, recordId, expectedRevision, requestId, reason | 無効化した記録。全公開版を閲覧対象から除外する。物理削除せず、宿題・請求・予約の扱いは別操作 |
| `lessonWriteResume` | studentId, requestId | 別タブで中断した書き込みを再開。受理済みの内容を使い、完了済みなら保存結果を返す |

成功は `{ ok: true, context }` を返し、書き込みには元の `operation`、recordId、版数、保存時刻を付けます。contextは先生専用で、student、slot、record（teacherNote含む）、previous（内部メモなし）、otherPrevious、openTasks、homeworkState、draft、draftTemplate、pending、slotChanged、lessonChoicesを持ちます。保存済みデータの端末キャッシュに入れず、画面を閉じるまでのメモリに保持します。

recordには `publishedRevision`（未公開は0）と `publishedAt` も返します。公開API共通の `lessonPublishedForStudent_(studentId)` は、対象生徒の有効記録ごとに完了済みの最新公開版を返します。生徒stateとparentData/familyDataの `lessonRecords` に載せるのは `{recordId,revision,date,start,min,subject,content,progress,nextFocus,homework,publishedAt}` だけです。内部メモ・報告下書き・書き込みpayload・生徒専用キーを返さず、MCPの取得内容へ追加しません。認証後に各経路で対象生徒を確定し、家族内でも選択した子のデータだけを返します。

期限の投影は `{due,dueMode,dueSubject,dueStart,nextLessonPending}`。record.homeworkは保存した定義を保ち、homeworkState/openTasks/公開版homeworkには解決した期限を返します。汎用taskAddは `dueMode`・`dueSubject` と任意の `afterSlotId` を受け取り、`lessonTaskAddFields_` が検証済み保存値を返します。taskDoneは所有者確認後に `lessonSetTaskDone_` を使い、doneAtと期限の固定を同じ行で更新します。不正入力は既存のlessonError形式で返します。

宿題の差分状態は `new`（未反映）、`changed`（変更あり）、`applied`（一致）、`held`（完了済み変更保留）、`withdrawn`（取り下げ済み）、`removed`（下書きから除去したが公開課題は残る）です。反映結果はadded/updated/unchanged/held/withdrawnの項目IDで返します。

未認証は既存の `badAuth`。入力不正は `validation`、対象不一致は `notFound`、版競合は `conflict`、途中処理は `pending` を `errorCode` として返す。競合時は入力を残し、「最新を確認」へ誘導し、自動上書きしません。

### サーバー側の検証

- ロック取得後に再読込し、対象生徒・slotの現在の所有者・recordの保存済み所有者を検証する。初回保存は在籍生徒の `booked` 枠だけ。`done` は保存の条件にしない。
- recordIdを受け取る操作は必ず保存されたstudentIdを照合する。taskIdだけ、シート行番号だけの更新はしない。
- 日付と時刻の正規化、文字数・配列数・必須値・型・重複itemIdを検証する。未知の書き込みフィールドを拒否し、reqで日時・生徒ID・完了・公開状態を上書きできないようにする。
- 入力テキストはプレーンテキストとして保存し、先頭 `=` などを数式として評価させない書き込み方法を共通化する。画面表示は `esc` またはtextContentを使う。
- 非在籍生徒の既存記録は先生が閲覧・訂正できる。新たな宿題反映は不可。対象slotが消失・他生徒に再割当、または日時・時間数・科目が変更されていれば新たな保存を止める。受理済み処理の再開は下記の復旧規則に従う。

### 再送・同時更新・途中失敗

`doPost` が `ScriptLock` をtry/finallyで取得・解放し、先生用取得と書き込みを直列化します。授業モジュールは二重ロックしません。取得タイムアウトはpendingを返します。同じrequestId・同じ正規化payloadの再送は以前の結果または未完了工程の再開にし、同じIDで内容が違えば拒否します。expectedRevisionが古ければ書き込まず競合を返します。

Sheetsの複数行書き込みはトランザクションではありません。書き込み前に全項目の検証を終え、`lessonWrites` にpendingの内容を保存します。固定IDでのupsertを順番に行い、最後にappliedと結果を記録します。pendingを認めた対象recordには別更新を受け付けず、先生の再試行または管理用復旧関数で完了させます。書き込み記録自体の保存に失敗した場合は後続処理を始めません。

新規に受理する記録保存のjournalだけに公開snapshotを含め、先生メモ→記録→公開snapshot→appliedの順で書きます。公開取得はsourceRequestIdがappliedの版だけを選び、途中で止まった新しい版を見せません。更新中は直前の完了済み公開版を維持し、初回保存中なら公開一覧は空です。旧pendingのjournalにはsnapshotを付加せず再開し、旧appliedの再送・報告下書き保存からも公開版を生成しません。過去記録を今後明示的に保存し直した場合は、その新しい版だけを公開します。

教師用の取得も同じロックとpending判定を使い、保存途中の異なる版の本文・内部メモを完成済みとして返しません。宿題反映は項目ごとに公開され得るため、途中失敗を「全件成功」と表示しません。既存の生徒GETは全件一括反映を保証しないことを前提に、個々のtasks行は1回のsetValuesで整合するよう更新します。

中断後に予約が取消・変更された場合でも、受理済みの記録・内部メモ・下書きは、元の生徒と授業日時を保持した履歴として完成させます。中断した宿題反映は、再開時に非在籍・予約変更を検出したら未反映項目の公開を停止し、書き込み記録をfailedで終えます。既に反映した宿題と完了履歴は残し、`partial: true`、failed項目ID、`retryRequired: false`、最新contextを返します。同じリクエストの再送でもこの結果を返し、既存の宿題は別操作で取り下げられます。

通信失敗と認証切れでは画面の入力と送信内容・requestIdを保持します。競合では最新内容と手元の入力を比較し、明示的に編集を続けるか最新へ入れ替えます。比較だけでは保存しません。別授業へ移動後の遅延応答はその画面を上書きせず、以前のトークンの応答で新しい先生ログインを失効させません。

## 5. 宿題と授業枠の変化

宿題反映時は `sourceRecordId + sourceItemId` が一致する課題だけをupsertし、ID・createdAt・createdBy・doneAtを保持します。未完了なら題名・期限を更新できます。完了済みで内容が変わった項目は変更せず「完了済みのため保留」と返し、再出題は新しいitemIdで作ります。

記録から宿題欄を消しても公開済み課題は自動削除しません。「取り下げ」でwithdrawnAtを記録し、生徒の未完了一覧・次回準備・MCP一覧から除外します。通常の再反映では取り下げを復活させません。既存の先生の `taskDel` も授業由来の課題はこの経路へ変更します。既存の学生作成課題の削除はそのままです。

次回準備は最新の未完了・未取り下げ課題を取得し、期限切れも出します。記録内の宿題下書きや前回時点の完了状態だけを表示しません。

`nextLesson` は対象生徒・同じ科目の `booked` 授業を全日付から探し、起点日時より後で最も早い開始日時を期限にします。元授業そのもの、offered、他生徒・他科目は除外します。授業記録からの宿題の起点は元授業の保存済み日時です。汎用taskAddでafterSlotIdを指定した場合は、その枠が本人・同科目のbookedであることを確認します。指定しない場合は保存時のJST日時を固定の起点とします。クライアントが起点日時を指定することはできません。

未完了の期限は閲覧時に解決し、次回授業の日時変更・取消・再割当・科目変更へ追随します。対象がなければ `nextLessonPending:true` で「次回の授業は未定」と表示します。「今日以降」に絞らないため、既に過ぎた対象を自動で次の授業へ飛ばさず、期限切れとして残します。日程の変化だけで課題の変更差分や再出題とは扱いません。

完了時には、その時点で解決した日付をdue、時刻をdueTimeへdoneAtと同じ行で保存し、完了後の日程変更で期限を動かしません。次回未定のまま完了した課題は空の期限を固定します。完了操作の同じ値での再送・記録の再反映で固定期限やdoneAtを上書きしません。明示的に未完了へ戻すと再び動的解決します。本文・期限種別・指定日の変更がある完了課題は従来どおり保留し、完了履歴を保ちます。

授業枠の解除・削除・取消があっても記録と宿題を連鎖削除しません。記録は作成当時のstudentIdと日時を保持し、取得時に「元の予約が取消／変更されています」と示します。別生徒に同じslotIdが割り当てられても、記録をその生徒へ渡しません。保存し直すには元の対象一致が必要です。取消後に残った宿題は先生が別操作で取り下げます。

## 6. 移行と戻し方

1. 開始時に2つの台帳をバックアップし、GASの公開版・Gitコミットを記録する。機能ごとにコミットを分け、Gitへの保存と本番反映の完了を区別する。
2. 新規シートを追加し、tasksの既存ヘッダーを確認して末尾列だけを追加する。想定と違う場合は移行を止める。移行は何度実行しても同じ結果にする。
3. `ensureLessonSchema_` が全対象のヘッダーを確認してから追加する。今回は既存tasksの12列を16列へ拡張し、lessonPublicSnapshotsを新設する。既存8列・12列・途中まで追加した正しい接頭辞を受け入れ、同じ準備を再実行できる。統合側の `ensureSchema_` のキャッシュキーも更新し、古い6時間キャッシュで列準備を飛ばさない。過去授業から架空の記録や宿題、公開版を自動生成しない。
4. `config.lessonCycleEnabled` を `off` にすると専用APIを停止し、画面は「準備中」を表示する（空またはonは有効）。GAS→画面の順に反映する。
5. ロールバックは機能を非表示にして書き込みを止め、追加シート・列を保持する。宿題取り下げを理解しない旧GASへ戻す場合は、そのまま戻すと課題が再表示され得るため互換版を用意する。稼働中データをバックアップで丸ごと上書きしない。

2026-09-08に本番の構造準備を実施済みです。tasks16列と空の公開snapshotシートを準備し、既存セル・数式・シートID・元の順序を保持したことを確認しました。既存の未公開記録から公開版は生成していません。両台帳の照合範囲と、別途実施したユーザー確認済みの科目1セル訂正は [SYSTEM.md 6-3節](SYSTEM.md#6-3-v49の反映と検証) に記録します。

## 7. 受け入れ条件

ローカルでは [授業APIテスト](../test/lesson-cycle.test.cjs) が保存・移行・参照保護・途中失敗・ダミー台帳のコピーからの復旧・HTTP認証とロック・公開APIへの混入防止を、[保存時公開・期限テスト](../test/lesson-publication-deadlines.test.cjs) が公開版の保存境界・旧処理の非公開互換・子別の公開範囲・次回期限の動的解決と完了固定を、[画面VMテスト](../test/lesson-cycle-ui.test.cjs) が再送・再ログイン時の入力保持・競合比較・遅延応答・端末保存の不使用を検証します。VMはブラウザの表示検証ではありません。[実GAS用検証関数](../test/gas-native-lesson-check.gs) は新規の架空台帳2冊だけを使う一時ヘルパーで、公開対象に含めません。保存時公開・先生メモ除外・動的期限・完了時固定を含む授業記録29項目が実GASで通過しました。追加機能全体のローカル355件・実GAS118項目と、本番準備・公開確認の状態は [SYSTEM.md 6-3節](SYSTEM.md#6-3-v49の反映と検証) に集約しています。

- 初回保存と同一requestIdの再送で記録1件。同じ画面からの再保存で同じ記録のrevisionが増える。
- 今後の新規保存で公開版が1件増え、先生メモと報告下書きは保存先・公開APIともに混入しない。旧pending/appliedの再送・過去の未公開記録・報告下書きの保存だけでは公開版が増えない。
- 記録保存の各行と完了receiptの前後で失敗させ、公開取得が未完了版を返さず、同じrequestIdの再開で1つの公開版へ収束する。voidで全公開版を非表示にする。
- 古いrevision、他生徒のslotId・recordId・taskId、無効token、停止生徒への新規宿題を拒否する。
- 記録保存後もslots.done、月次集計、plans、入金管理、Calendar、Gmailが不変。
- 宿題反映の再送で増殖せず、生徒が完了を付けた後の再反映でdoneAtが変わらない。
- 宿題2件目で意図的に書き込み失敗しても、再試行で重複せず収束し、失敗を保存成功と表示しない。
- 完了済み宿題の変更、取り下げ後の再反映、項目の並べ替えで完了履歴と対応IDが維持される。
- 次回の同科目bookedだけを選び、未予約・offered・別科目・別生徒・取消・日程変更・期限切れを扱える。完了後は期限を固定し、再反映・通信失敗の再試行で完了日時と固定期限を保つ。
- 別生徒・別科目・未来の記録を前回として選ばない。60件超・期限なし・期限切れ・次回未予約を扱える。
- 先生メモに識別用文字列を入れ、生徒state・保護者API・MCP・生成下書き・端末キャッシュのどこにも含まれない。
- 記録のある予約が削除・解除・別生徒に変更された後も、元の先生用履歴を保持し、他生徒へ漏れない。
- 改行、HTML文字、数式に見える入力をテキストとして保存・表示。通信エラー・認証切れ・版競合で入力を保持する。
- バックアップからの復旧手順と、pending処理の再開をローカルのダミーデータで検証する。
- 本番確認が必要な場合は `【テスト】` で始まる生徒だけを使う。実生徒の記録・予約は変更しない。
