## 書き方のルール

- 後続作業に影響する未解決事項を、背景・次の行動・関連資料・追加日とともに残す。既存項目があればそこを更新し、一時的な試行や会話ログは書き溜めない。
- 仕様や検証結果は該当する正本に置き、ここから参照する。着手中は `[着手中]`、未定の選択肢は「候補・未定」と明記する。
- 完了した項目はこの一覧から外し、必要な日付・コミット/GAS版・判断理由を下記「済み」の参照先へ残す。
- 優先度は A(運用に支障・安全性)/ B(あると楽になる)/ C(いつか)の3段階。

## A: 優先度が高い(安全性・運用に直結)

### 対面・オンラインの同時受講人数
- **要件**: 対面は同時2人まで、オンラインは1対1。授業形式は基本固定だが、変更できるようにしたいという希望がある。個別の生徒名・形式の割当は公開資料に載せない。
- **現状**: `adminOffer_` は全生徒の同日・同開始時刻を重複としてスキップする。時間区間・人数・授業形式による判定はなく、開始時刻をずらした重なりも検証していない。`accept_` / `adminFinishOffered_` にも定員判定はない。
- **対応案**: 生徒の普段の形式を初期値として授業ごとに形式を保存する。どの時間帯も対面2人以内となる共通判定を、案内・確定・形式変更・一括処理に適用する。同じ生徒の二重予約、終了と次の開始が一致する境界、再送・同時操作も確認する。形式変更で過去授業を書き換えず、Meet発行も授業形式に合わせる。
- **詰める点**: オンライン中は対面を含む他の授業を入れない、案内中も席を確保する、取消依頼中は席を維持する、という設計案。既存枠の形式の補完と確定済み枠の形式変更時の扱いも決める。
- **関連**: `gas/Code.gs` の `adminOffer_` / `accept_` / `adminFinishOffered_` / `createCalEvent_`、[月間承認と請求](SYSTEM.md#5-1-月間承認と請求)。
- **追加日**: 2026-09-08

### 兄弟姉妹と保護者メール
- **要件**: ときどき受講する兄弟姉妹も生徒として分け、保護者は両方をまとめて管理したい。保護者自身が登録するメールへ月間料金・請求などの重要な連絡を送り、ログインや再設定にも使いたい。
- **現状**: 保護者認証は生徒ごとに1件。メール欄は `students.email` で、確認済みの保護者メールや複数の子どもの切替は未実装。
- **対応案**: 生徒の予定・宿題・授業記録・料金承認・請求は子ども別に保ち、独立した保護者アカウントと閲覧できる子どもの対応を持つ。先生の招待・紐付け確認でアクセスを付与し、同姓や同じメール文字列だけで兄弟を結び付けない。保護者画面は子どもの切替と一覧を用意する。家族合算の請求発行は別途採否を決める。
- **メール案**: 確認メールで受信できることを確かめたアドレスをログインID・通知先に使い、パスワード再設定、メール変更時の本人確認も設計する。重要連絡は保護者画面にも残し、送信失敗を先生が把握できるようにする。通知対象・まとめ方・送信上限と再送時の重複対策を決め、既存の生徒宛て連絡先とは区別する。
- **詰める点**: 既存の生徒別保護者認証からの移行、複数保護者の扱い、子どもの追加・停止・紐付け解除時の権限、通知するタイミング。既存の生徒別認証だけで家族全体へのアクセスを広げない。
- **関連**: [PARENT_AUTH.md](PARENT_AUTH.md)、`gas/Code.gs` の保護者API・メール送信、[OWASPのメールIDと本人確認](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html#usernames)、[Apps Script送信上限](https://developers.google.com/apps-script/guides/services/quotas)。
- **追加日**: 2026-09-08

## B: あると楽になる

### 授業案内の一括確定
- **要件**: 月12回など複数の案内を1件ずつ確定すると毎回の読込が長い。対象の日時を選び、まとめて承認・確定したい。
- **対応案**: 全選択・個別選択と確認一覧を用意し、1回の送信と最後の画面更新で処理する。同時受講人数の共通判定を先に整え、選択した授業同士も含めて時間帯・本人・月・科目ごとの承認回数を確認する。月間料金への保護者承認と、授業日時の確定はそれぞれ維持する。
- **完了条件案**: 不可の日時と理由が分かり、保存途中で切れても再送で授業・Calendar・通知が二重にならない。確定済み・未確定・通知失敗を区別し、途中失敗を全件成功と表示しない。1件確定を単純に連打するだけの構成にしない。
- **関連**: `yoyaku/index.html` の案内承認、`gas/Code.gs` の `accept_`、`gas/BillingApproval.gs`。
