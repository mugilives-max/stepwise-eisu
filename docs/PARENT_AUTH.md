# 保護者専用認証

最終更新: 2026-09-09。保護者認証・保護者メールの仕様と、固有の検証・復旧条件の正本。変更・再検証するときに参照する。未完了事項は [FUTURE_WORK.md](FUTURE_WORK.md)、実際の公開版・確認結果は [SYSTEM.md](SYSTEM.md#6-更新デプロイ手順) で管理する。

以下の家族方式はGAS v48と公開画面へ反映済み。2026-09-09から保護者アカウントに生徒を紐付ける家族方式へ統一。旧生徒別ログイン・設定コード発行・セッションによる閲覧は停止し、旧画面リンクも家族方式を表示する。旧認証データは復元用に保持するが利用しない。既存の家族アカウントと紐付けは変更しない。未登録の場合のみ招待による登録が必要。検証範囲は [SYSTEM.md](SYSTEM.md#6-2-v48の反映と検証) を参照する。

## 生徒グループと共有保護者ログイン（ローカル実装・未反映）

### 課題と決定

保護者個人を登録する導線は不要。生徒グループに保護者用アカウントを1つ対応させる。1人は単独グループ、兄弟は同じグループ。父母などは同じメール・パスワードを複数端末で共有する。既読は個人別ではなくアカウント単位。請求・授業・成績の正本は引き続き生徒単位であり、グループをまとめても業務記録は移動・削除しない。

### 登録・まとめ方

1. 新規生徒の登録時に単独グループを作る。グループ作成だけ失敗した場合は生徒登録を取り消さず、案内作成から復旧する。既存の未所属生徒は管理画面に表示し「保護者の登録案内を作成」で単独グループを作る。読み取りで既存データを自動移行しない。
2. 生徒ページの「生徒グループ・保護者ログイン」から移動先を選ぶ。「このグループにまとめる」で、残すログインと元グループへの影響を確認する。他の生徒は動かさず、空になった元グループは停止する。既存の複数所属は推測で統合しない。
3. 登録リンクをコピーして個別に渡す。コードは24時間・1回限り、URL fragmentを画面で読み取ったら除去する。保護者本人がメールとパスワードを設定し、確認メールを開く。先生はパスワードを発行・閲覧しない。
4. 登録待ちなら案内再発行、メール確認待ちなら再送案内、登録済みならログイン・再設定案内を使う。未確認メールでパスワードを忘れてもメールで復旧できる。

### セッションと反映上の注意

既存の tokenHash 列に期限付きハッシュ配列を保存する。平文トークンは保存しない。旧単一ハッシュも期限内は読める。新規ログインで他端末を失効させず、期限は各端末で独立。20件到達時は既存端末を勝手に追い出さず案内する。旧版は配列形式を認証できないので、差し戻す場合は全端末の再ログインが必要。所属移動は両グループを先に失効し、元を解除してから移動先へ追加する。失敗時は権限拡大を避け、同じ移動の再試行で完了する。実データの移行・本番反映は未実施。

メール確認は受信先の確認であり、保護者関係の証明を代替しない。先生が関係を確認して子どもを紐付ける。同姓や同じメールを根拠に、別アカウントを結合したり、閲覧できる子どもを増やしたりしない。同じメールの重複登録は拒否する。既存の生徒別アカウントからも自動的に家族の権限を与えない。

### 再設定・変更・停止

- パスワードを忘れた場合はメールで再設定する。登録の有無によらず同じ受付案内を返し、登録先メールに再設定リンクを送る。未確認メールでも、リンクを確認してパスワードを再設定すれば利用開始できる。
- メール変更には現在の家族ログインとパスワードが必要。変更申込時にログインを失効させ、新しいメールの確認が終わるまでは旧メールを維持する。届かなければ旧メールでログインして変更を申し込み直せる。
- 招待コードは24時間・一度限り。登録済みの家族には招待コードを再発行せず、メールでパスワードを再設定する。
- メール確認・再設定のリンクは30分・一度限り。再発行で前の同種リンクを失効させる。再発行は1分以上の間隔、種類ごとに1時間5回まで。確認メールが届かない場合は受信箱・迷惑メールを確認してから再発行する。
- 生徒の停止・専用リンク再発行、家族の利用停止、子どもの紐付け変更、パスワード再設定、メール変更に伴って家族ログインと以前の確認リンクを失効させる。利用再開や再紐付けで古いログインは復活しない。
- 停止中の生徒は家族ページに表示せず、直接のデータ取得も拒否する。既存の紐付けは保持できるが、停止中の新規紐付け・解除後の再紐付けはできない。子どもの紐付けがなくても家族ログイン自体は可能で、先生による紐付け待ちとして扱う。

### 家族認証の保存と権限

- パスワードは12〜128文字で、文字種の強制や前後の空白削除はしない。アカウント別のランダムなsaltと、既存のPBKDF2-HMAC-SHA256（600,000回）を使用する。先生の認証情報は流用しない。
- ログイン誤入力5回で15分停止する。セッションは端末ごとに12時間、同時20件まで保持する。通常ログアウトは該当端末だけ、パスワード・メール・所属変更や停止では全端末を失効させる。ブラウザでは `sessionStorage` の `sw_ft_v1` に保持し、既存生徒別の保護者セッションと分ける。
- 招待・セッション・メール確認の秘密はハッシュだけを台帳に保存する。招待の誤入力5回で招待を無効化する。確認リンクも用途・家族・有効期限・使用済み状態・認証変更の版を照合する。
- 確認用の秘密はURLのフラグメントで受け取り、画面が読み取った後にアドレス欄から除く。秘密、パスワード、メール本文をログ・管理画面・業務通知台帳に保存しない。
- `familyAccounts`（19列）、`familyLinks`、`familyChallenges`、`familyOutbox` を追加する。正確な列順と保存処理は [FamilyPortal.gs](../gas/FamilyPortal.gs) の定数を正本とし、ここには複製しない。既存 `parents` は変更しない。
- 全操作は既存のScriptLock内で実行する。子どもの閲覧・承認のたびに、確認済みアカウント・現在のログイン・先生の紐付け・生徒の在籍状態を照合する。先生用APIや生徒別保護者APIへの家族トークンの流用は拒否する。
- 家族への返却項目は保護者向けに限定する。他の子どもの予定、先生の内部メモ、報告下書き、台帳備考、認証秘密は返さない。家族管理と紐付け変更は先生の認証だけに開放し、MCPからは操作させない。

### 保護者へのメール通知

対象は、月の回数・料金の確認依頼、請求の記録、請求の取消。確認済みの登録メールへ、通知の種類・対象月と家族ページの案内を送る。金額・学習内容・内部メモは本文に含めず、詳しい内容はログイン後に子どもを選んで確認する。

送信履歴は管理画面「家族・保護者への通知」で確認する。同じ業務の通知を二重作成しないよう、家族と出来事を識別するキーで記録する。再試行時にもメール・紐付け・生徒の在籍を確認し、変更されていれば送信を取り消す。

| 送信状態 | 扱い |
|---|---|
| 未送信・送信上限等による失敗 | 実送信前と確認できた業務通知だけ、先生が再試行できる |
| 送信済み | 再送しない |
| 結果不明（`uncertain`） | メール呼出直前から記録。応答不明や送信後の記録失敗では二重送信の可能性があるため、自動・手動とも再送しない。先生が受信状況を確認する |
| 送信取消 | メール変更・子どもの解除等で送信条件が変わったため送らない |
| テストによる送信省略 | テスト用の家族には実送信しない |

メール送信と台帳保存を一つの確定処理にはできないため、「結果不明」を送信失敗と決め付けない。通知の失敗で回数・料金・請求の保存を失敗に巻き込まず、管理画面へ通知確認の案内を返す。確認・再設定メールの秘密は保存していないので、先生による同じメールの再送は行わず、保護者から新しいリンクを発行する。

紐付く生徒が全員 `【テスト】` の家族は実メールを抑止する。テスト生徒だけで作成した家族にはテスト用の印を保存し、後で全員の紐付けを解除しても抑止が外れない。実配信の検証は宛先・通数について個別に許可された範囲だけで行い、通常のテストに混ぜない。

### 家族API

すべてPOST。公開操作は `action`、管理操作は `action:admin` と `op` を指定する。認証失効時は `familyAuthRequired:true` を返す。パスワードは `pass`、家族トークンは `ftoken` として送る。

| 公開操作 | 必須入力 | 成功時・用途 |
|---|---|---|
| familyRegister | inviteCode、email、pass | 確認メールを発行。verificationRequired、mailStatus。ログインはまだ与えない |
| familyVerify | challenge | 初回または変更先メールを確認。確認後はメール・パスワードでログイン |
| familyResendVerification | email、pass | 未確認メールを再発行。登録内容によらず共通の受付案内 |
| familyLogin | email、pass | ftoken、家族の表示情報、現在閲覧できる子どもの一覧 |
| familyHome | ftoken | 家族の表示情報と現在の子ども一覧 |
| familyData | ftoken、studentId | 指定した子どもの保護者向けデータのみ |
| familyPlanDecide | ftoken、studentId、ym、approve、expectedRevision | 表示した子どもの回数・料金の版への回答。任意のmemo。更新後の本人データを返す |
| familyLogout | ftoken | 失効。古いトークンの再送で新しいログインを失効させない |
| familyResetRequest | email | 共通の受付案内。確認済みメールだけに再設定リンクを送る |
| familyResetConfirm | challenge、pass | 新しいパスワードへ変更し、ログインを失効 |
| familyEmailChange | ftoken、email、pass | 現在のパスワードを確認し、新しいメールへ確認リンクを送る。申込時にログイン失効 |

| 先生の操作 | 必須入力（先生tokenは共通） | 成功時・用途 |
|---|---|---|
| familyList | なし | 家族・子ども候補・直近100件の通知状況。秘密は返さない |
| familyCreate | label、studentIds | 新規家族と紐付けを作成し、招待コード・有効期限を一度だけ返す |
| familySetChildren | familyId、studentIds | 閲覧できる子どもを置き換え、旧ログインを失効 |
| familyInvite | familyId | 未登録の家族の招待を再発行 |
| familySetActive | familyId、active | 家族の利用停止・再開。旧ログインは復活しない |
| familyRetryNotifications | ids（10件以内） | 再試行できる業務通知だけを処理。認証メール・結果不明は対象外 |

## 廃止した生徒別方式の履歴

以下は復旧判断のための過去記録であり、現在の利用・設定手順ではない。2026-09-09に入口・設定・認証を停止した。

以下はv45からの生徒別認証。生徒ごとの専用リンクとパスワードを引き続き利用できる。きょうだいの切替は上記の家族方式で提供し、この方式の閲覧範囲は一人のまま維持する。

## 利用の流れ

1. 先生が管理画面の生徒カルテ「保護者用パスワード」で設定コードを発行する。
2. 画面に一度だけ表示する6桁のコードと有効期限を、先生から保護者にLINEなどで直接伝える。自動送信はしない。
3. 保護者は生徒の専用リンク→保護者→「初めて・パスワードを忘れた方」でコード、新しいパスワード、確認入力を送信する。
4. 設定後は保護者専用パスワードでログインし、その生徒の授業・支払い・月間承認を利用する。
5. 終了時はログアウト。通信失敗時は完了扱いにせず再試行する。

この方式は生徒ごとに1保護者アカウント。
パスワードは12〜128文字、文字種の強制なし、前後の空白は削除しない。

## 認証と保存

- 先生のパスワード・PIN・adminTokenを保護者認証に流用しない。
- `parents` シートを新設。列順: `studentId, passSalt, passHash, setAt, lastLogin, failCount, lockUntil, setupHash, setupExpiresAt, setupFailCount, tokenHash, tokenExpiresAt`。
- パスワードは生徒別ランダムsaltとPBKDF2-HMAC-SHA256（600,000回）で保存。既存ライブラリをコードに同梱し、実行時の外部通信はない。先生側の既存ハッシュは今回変更しない。
- 設定コードは24時間・1回限り。誤入力5回でコードを無効化し、先生の再発行が必要になる。再発行は前のコードを置き換える。
- コード発行時に既存セッションは無効化する。連絡不達に備え、旧パスワードは新しい設定が成功するまで利用可能。
- ログイン誤入力5回で15分ロック。時間経過後の次の試行、または正しい設定コードによる再設定で解除。
- セッションは12時間、生徒ごとに同時1つ。トークンはハッシュだけを保存し、他生徒や先生のAPIでは受け付けない。
- 専用リンク再発行・生徒の停止時に、保護者セッションと未使用設定コードを無効化する。復帰しても古いトークンは復活しない。
- ブラウザのセッションキーは生徒リンク別の `sw_pt_v2:`。旧 `sw_pt` を削除し、旧 `students.parentToken/parentExp` の値はサーバーで一切受け付けない。旧列は互換性のため残す。
- カルテは設定状況・設定日時・最終ログイン・設定コード有効期限だけを返す。ハッシュやコードはカルテキャッシュに含めない。
- `parentData` は返却項目を限定し、管理台帳の備考・内部行番号・面談記録・認証情報を含めない。月間計画に明示したメモは既存の共有情報として残す。
- MCPの権限は閲覧のみのまま。ログに残すパラメータを許可リストにし、誤って渡された保護者認証情報を保存しない。

暗号設定の参照: [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)、[noble-hashes](https://github.com/paulmillr/noble-hashes)。

| 操作 | 入力 | 成功時 |

| admin / parentIssueSetupCode | 有効な先生token、studentId | setupCode、expiresAt、parentAuth。コードは発行応答のみ |
| parentSetup | k、setupCode、pass | ptoken |
| parentLogin | k、pass | ptoken |
| parentLogout | k、ptoken | ok。失効済みの再送も成功、新しいセッションを巻き込まない |
| parentData | k、ptoken | 本人生徒の保護者向けデータ |
| parentPlanDecide | k、ptoken、ym、approve、memo、expectedRevision | 表示した回数・料金の版への回答。詳細は [月間承認と請求](SYSTEM.md#5-1-月間承認と請求) |

全POSTは既存ScriptLock内で読み込み・検証・保存。認証失効は `parentAuthRequired`、初回未設定は `needSetup` を返す。設定コード発行はMCP・生徒・保護者には開放しない。

## 今後の再反映時の順序と確認

一般の退避・ソース照合・公開手順は [SYSTEM.md 6章](SYSTEM.md#6-更新デプロイ手順)。以下は認証変更に関係する条件。文書変更や無関係な画面変更で一律に実行しない。

1. 認証コードの変更は `npm run check` と影響するテストで検証する。家族方式は `node --test test/family*.test.cjs`、既存方式は `node --test test/parent-auth*.test.cjs` が入口。共通の暗号・HTTP分岐・権限・返却項目を変更した場合は、影響する両方式と業務APIを含め、必要に応じて `npm test` を実行する。依存環境の初期化・更新時は `npm ci --ignore-scripts`、暗号ライブラリや生成処理を変えた場合は `npm run build:crypto` を先に実行し、生成コードを含めて検証する。
2. GASサービス依存処理・暗号処理・保存形式を変えた場合は、公開前に対象の実GAS検証を行う。家族方式の正本は [test/gas-native-family-check.gs](../test/gas-native-family-check.gs) の `stepwiseNativeFamilyCheck`、既存方式は [test/gas-native-auth-check.gs](../test/gas-native-auth-check.gs) の `stepwiseNativeAuthCheck`。一時追加して新規の架空台帳へ参照先を切り替える。既存台帳・先生認証・Script Propertiesは読まず、実メール・カレンダーを呼び出さない。家族の送信判定はメモリ内の代替処理で検証する。既存の `LEDGER_ID` は書き換えず、検証用ファイルは公開前に削除する。
3. 初回運用前や認証負荷・ロック処理の変更時は、PBKDF2の実行時間と並行POSTのScriptLock（10秒待ち）を実環境で確認する。画面・HTTP検証は参照先を確認し、許可された架空の `【テスト】` 生徒・家族で登録→メール確認→ログイン→子別閲覧→ログアウト→再設定を試す。実配信を含める場合は、対象の宛先・通数の許可とテスト用の送信制限を別途確認する。支障が出た場合は公開・運用開始を止め、ハッシュ回数を安易に下げず認証基盤を再検討する。
4. `parents` または家族用シートの導入・構造変更時は台帳を退避・比較し、列順と作成権限を確認する。ソース保存後、**既存公開版を切り替える前に**管理側でスキーマを準備し、利用者の最初のPOST任せにしない。既存公開版がバージョン固定であることも確認する。準備関数とスキーマキャッシュの現行キーは [SYSTEM.mdの反映手順](SYSTEM.md#6-更新デプロイ手順) と `gas/Code.gs` / `gas/BillingApproval.gs` を参照し、過去版の例を再実行しない。
5. 認証APIと画面を同時変更する場合はGAS→HTMLの順で公開し、テスト生徒で変更機能と表示/API版の一致を確認する。台帳エラーや許容できない待ち時間が出た場合は運用を止め、下記「戻し方」に従う。
6. 保護者への初回案内は、本番テストの結果を先生が確認してから行う。実生徒へのコード発行・送信は対象と依頼を確認して行い、テストの一部として自動実行しない。

`ensureSchema_`は全POSTの冒頭で呼ばれる。認証用シートの列不一致・作成権限エラーは、保護者以外の予約・成績・管理・MCPのPOSTも停止させる。列を上書きして通す処理はないため、公開前の準備に失敗した状態では公開しない。

旧フロントから新GASへの先生パスワードによる保護者ログインは失敗する。新フロントから旧GASへの設定操作は未対応で失敗するため、GAS→HTMLの順序を守る。
前の画面に残った旧トークンを移行して使う処理は設けない。

## 戻し方

画面は対象コミットのrevertで戻す。GASの問題は既存デプロイの版を戻せるが、v44へ戻すと**先生と共通の保護者認証も復活する**。保護者運用開始後は単純に旧版へ戻さず、保護者操作を停止する修正版で対処する。
家族方式を含まない版に戻すと、家族ログイン・メール確認・家族通知が利用できなくなる。運用開始後は影響する入口を停止して案内し、生徒別方式へ家族の権限・認証秘密を自動で移さない。`parents` と家族用シートは保持し、他の台帳の列や既存データを削除しない。コード修正の戻しとデータ復旧は分け、全台帳の巻き戻しで既存授業を失わないようにする。
