# 保護者専用認証

作成日: 2026-09-07。`codex/parent-auth` に実装。本番へは未反映。
既存コードの基準: `30e1ce8a05008e6ef32ee5323226a6d1e9b0d67a`。
ユーザー確認: 現在の保護者モード利用者はなく、専用認証への移行を進めてよい。

## 利用の流れ

1. 先生が管理画面の生徒カルテ「保護者用パスワード」で設定コードを発行する。
2. 画面に一度だけ表示する6桁のコードと有効期限を、先生から保護者にLINEなどで直接伝える。自動送信はしない。
3. 保護者は生徒の専用リンク→保護者→「初めて・パスワードを忘れた方」でコード、新しいパスワード、確認入力を送信する。
4. 設定後は保護者専用パスワードでログインし、その生徒の授業・支払い・月間承認を利用する。
5. 終了時はログアウト。通信失敗時は完了扱いにせず再試行する。

初回は生徒ごとに1保護者アカウント。兄弟姉妹の一括切替・複数保護者の個別アカウントは将来の拡張。
パスワードは12〜128文字、文字種の強制なし、前後の空白は削除しない。

## 認証と保存

- 先生のパスワード・PIN・adminTokenを保護者認証に流用しない。
- `parents` シートを新設。列順: `studentId, passSalt, passHash, setAt, lastLogin, failCount, lockUntil, setupHash, setupExpiresAt, setupFailCount, tokenHash, tokenExpiresAt`。
- パスワードは生徒別ランダムsaltとPBKDF2-HMAC-SHA256（600,000回）で保存。既存ライブラリをコードに同梱し、実行時の外部通信はない。先生側の既存ハッシュは今回変更しない。
- 設定コードは24時間・1回限り。誤入力5回でコードを無効化し、先生の再発行が必要になる。再発行は前のコードを置き換える。
- コード発行時に既存セッションは無効化する。連絡不達に備え、旧パスワードは新しい設定が成功するまで利用可能。
- ログイン誤入力5回で15分ロック。時間経過後の次の試行、または正しい設定コードによる再設定で解除。
- セッションは12時間、生徒ごとに同時1つ。トークンはハッシュだけを保存し、他生徒や先生のAPIでは受け付けない。
- 専用リンク再発行・生徒の停止時に、保護者セッションと未使用設定コードを無効化する。復帰しても古いトークンは復活しない。
- ブラウザのセッションキーは生徒リンク別の `sw_pt_v2:`。旧 `sw_pt` を削除し、旧 `students.parentToken/parentExp` の値はサーバーで一切受け付けない。旧列は互換性のため残す。
- カルテは設定状況・設定日時・最終ログイン・設定コード有効期限だけを返す。ハッシュやコードはカルテキャッシュに含めない。
- `parentData` は返却項目を限定し、管理台帳の備考・内部行番号・面談記録・認証情報を含めない。月間計画に明示したメモは既存の共有情報として残す。
- MCPの権限は閲覧のみのまま。ログに残すパラメータを許可リストにし、誤って渡された保護者認証情報を保存しない。

暗号設定の参照: [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)、[noble-hashes](https://github.com/paulmillr/noble-hashes)。

## API

| 操作 | 入力 | 成功時 |
|---|---|---|
| admin / parentIssueSetupCode | 有効な先生token、studentId | setupCode、expiresAt、parentAuth。コードは発行応答のみ |
| parentSetup | k、setupCode、pass | ptoken |
| parentLogin | k、pass | ptoken |
| parentLogout | k、ptoken | ok。失効済みの再送も成功、新しいセッションを巻き込まない |
| parentData | k、ptoken | 本人生徒の保護者向けデータ |
| parentPlanDecide | k、ptoken、ym、approve、memo | 既存の月間承認結果 |

全POSTは既存ScriptLock内で読み込み・検証・保存。認証失効は `parentAuthRequired`、初回未設定は `needSetup` を返す。設定コード発行はMCP・生徒・保護者には開放しない。

## 反映順序と確認

1. 先生・他AIがGASと同じファイルを同時編集中でないことを確認。mainの最新状態と作業ブランチの差分を再確認する。
2. 予約・塾管理の2台帳をコピーして退避。実稼働GASとローカル基準の一致を確認する。
3. `npm ci --ignore-scripts`、`npm run build:crypto`、`npm run check`、`npm test`。生成済み暗号コードも含むCode.gs全文を対象とする。
4. 本番公開前に、架空の【テスト】生徒だけを入れた台帳とGASの検証環境で確認する。予約台帳への紐付け・`LEDGER_ID` が検証用を指すこと、カレンダー・メール通知がoffであることを確認してから、コード発行→設定→ログイン→ログアウト→再設定を試す。600,000回のPBKDF2の実行時間を測り、認証中の別POSTがScriptLockの10秒待ちで失敗しないかも確認する。支障が出る場合は本番を公開せず、ハッシュ回数を安易に下げずに認証基盤を再検討する。
5. 本番台帳の`parents`同名シートが未作成か、先頭12列が上記の列順と一致していることと、シート作成権限を確認する。本番GASのソースを保存した後、**既存公開版を切り替える前に**、管理側で下記の準備関数を一度実行して結果を確認する。一般利用者の最初のPOST任せにしない。既存公開版はバージョン固定であることを事前に確認する。
6. **GASを先に**既存デプロイの新バージョンとして反映。テスト生徒だけで疎通と設定・ログイン・ログアウトを再確認する。公開後に台帳エラーや許容できない待ち時間が出た場合は、保護者運用を開始せず旧GAS版へ直ちに戻し、原因を修正する。
7. kanri/yoyakuのHTMLをPagesへ反映。初回はキャッシュを避けて表示・API版一致を確認する。
8. 先生が画面でテスト生徒の結果を確認後、必要な保護者へ初回設定を案内する。今回実生徒へのコード発行や連絡は行っていない。

準備関数はエディタで実行する一時的な関数。台帳の退避と列確認を終えてから使い、確認後に削除する。既存の`setup()`は初期設定用なので、移行目的で再実行しない。

```js
function prepareParentAuthSchema() {
  var lock = LockService.getScriptLock();
  lock.waitLock(10000);
  try {
    CacheService.getScriptCache().remove('schemaOk14');
    ensureSchema_();
    Logger.log('保護者認証のスキーマ準備完了');
  } finally { lock.releaseLock(); }
}
```

`ensureSchema_`は全POSTの冒頭で呼ばれる。`parents`の列不一致・作成権限エラーは、保護者以外の予約・成績・管理・MCPのPOSTも停止させる。列を上書きして通す処理はないため、公開前の準備に失敗した状態では公開しない。

旧フロントから新GASへの先生パスワードによる保護者ログインは失敗する。新フロントから旧GASへの設定操作は未対応で失敗するため、GAS→HTMLの順序を守る。
前の画面に残った旧トークンを移行して使う処理は設けない。

## 戻し方

画面は対象コミットのrevertで戻す。GASの問題は既存デプロイの版を戻せるが、v44へ戻すと**先生と共通の保護者認証も復活する**。保護者運用開始後は単純に旧版へ戻さず、保護者操作を停止する修正版で対処する。
parentsは追加データだけなので、他の台帳の列や既存データを削除する必要はない。コード修正の戻しとデータ復旧は分け、全台帳の巻き戻しで既存授業を失わないようにする。
